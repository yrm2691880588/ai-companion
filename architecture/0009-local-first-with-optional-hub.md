# 本地优先 + 可选自建中心

## 背景

多端形态有四种：单机、主从、中心服务、点对点。用户需要手机与电脑数据互通，
但项目是开源自部署，不能假设有官方服务器，也不能让用户为了聊天去维护服务器。

## 决定

- 默认形态：**本地优先（local-first）**——每台设备都有完整本地数据库，断网可完整使用；
- 同步是增强：同一账号/同一配对下的设备之间同步；
- **可选自建中心**：愿意多端实时同步的人，可以自建一个同步服务（后续提供 Docker 镜像）；
- 不做官方托管服务；
- 不采用主从（一台必须常开）与纯点对点（NAT 穿透复杂）。

## 理由

本地优先最符合开源自部署：安装即用、隐私最好、断网可用。
自建中心作为可选，既满足多端实时，又不把项目绑在官方服务器上。

## 后果

- 数据模型必须支持“本地写入 + 后续合并”，不能依赖中心库自增 ID；
- 需要全局唯一 ID（UUID/ULID）与设备标识；
- 同步服务是可选的，核心功能不能依赖它；
- 部署文档要区分“单机模式”和“多端模式”。
