# 方向重排：先定多端与同步的基本盘，再做体验

## 背景

原计划先完成单机版七项体验改动（spec 0001），再考虑多端。但用户指出：
多端与同步会决定数据模型、身份体系与部署形态；若先按单机做完再拆同步，会返工。
这个判断成立——同步不是“加一个接口”，而是改数据所有权与冲突模型。

## 决定

- 暂停 `implement`，先把“多端 + 同步 + 开源分发”作为**大工程**规划（wayfinder 方式）；
- spec 0001 保留为“体验层 backlog”，不废弃，但在同步架构定稿前不施工；
- 规划顺序：产品形态 → 数据所有权 → 配对与同步模型 → 客户端形态 → 本期首个可交付切片；
- 在计划经用户确认前，不写代码。

## 理由

同步架构一旦定错（例如假设“最后写入胜出”），后续会话、记忆、演练、人设版本都要改；
先定基本盘，再在其边界内做体验，才不返工。

## 后果

- 短期看不到 UI 变化，但避免了结构性返工；
- 需要先回答一组产品/架构问题（见 wayfinder 决策票）；
- spec 0001 的七项功能要等架构确认后重新排序。
