# 语音走本机后端中转，前端不接触供应商 Key

## 背景

语音需要调用供应商的 ASR/TTS 云 API。若前端直连，API Key 会暴露在浏览器里，
且手机端要重复实现一遍密钥管理与签名。

## 决定

- 音频上传、识别、合成全部经本机后端中转；
- 供应商 Key 只保存在后端（与对话模型 Key 同一套加密存储）；
- 前端只负责录音、播放、以及显示识别出的文字；
- 接口形态按“可被手机浏览器复用”设计，不依赖桌面独有能力。

## 理由

Key 不进前端是硬约束；后端中转也让换供应商、加限流、做成本统计都集中在一处。

## 后果

- 音频要过一遍本机，弱网下延迟比直连高；
- 需要定义音频格式、大小上限与超时；
- 后端要能处理并发录音上传，不能阻塞对话线程。
