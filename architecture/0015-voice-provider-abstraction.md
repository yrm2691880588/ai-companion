# 语音：火山为主，抽象多供应商；预置音色并预留克隆

## 背景

用户主要使用火山引擎（豆包语音），但要求支持其他供应商；同时希望保留音色克隆
与音色参数调节的可能，以提升体验。

## 决定

- 语音供应商抽象为统一接口：`transcribe(audio)` 与 `synthesize(text, voice_id, params)`；
- 首个实现：火山引擎；接口层不写死任何火山专有字段；
- 音色：读取供应商的预置音色列表，用户为伴侣挑选；
- 预留扩展位：
  - 音色克隆（上传样本）——本期只留数据结构与入口占位，不实现；
  - 音色参数（语速、音调、音量、情感）——供应商支持则透传，不支持则忽略；
- 语音供应商配置与对话模型供应商分开，互不影响。

## 理由

绑定单一供应商会在成本、区域可用性、手机端适配上失去退路；而抽象层成本不高，
只要一开始不把火山字段写进业务代码即可。

## 后果

- 需要一张语音供应商配置表，与 `provider_settings` 分开；
- 音色列表要做缓存，避免每次打开设置都打供应商接口；
- 克隆与参数调节要以“能力声明”的方式表达，前端按能力显示，不假设都有。
