# 先做开源可下载项目，官方托管后置

## 背景

产品有两条路：国内正规运营（备案、实名、审核、主体）与 GitHub 开源自部署。
当前没有公司主体、备案与审核人力，直接做前者会把开发拖进合规流程。

## 决定

- 形态：**GitHub 开源、可下载自部署**；官方托管服务作为长期可选项，不在本期；
- 协议：MIT 或 Apache-2.0（二选一，倾向 MIT，简单）；
- 成人内容：**默认关闭**，由部署者在设置里显式开启并确认 18+；
- 登录：默认**本地单用户模式**（免登录），多用户手机验证码登录作为可选项；
- 责任：README 与首次启动页写明“18+、自部署者负责当地法律与内容合规”；
- 项目方不托管用户内容，不提供在线服务。

## 理由

开源能先验证产品、积累口碑与贡献者，成本最低；托管运营需要主体、备案、审核与客服，
在体验尚未验证前投入不划算。

## 后果

- 不能依赖“平台审核”兜底，内容边界必须内置在提示词与代码里；
- 需要把“本地单用户模式”做成默认路径，短信配置变成可选；
- 仓库曝光后，合规声明与内容开关必须清晰，避免被判定为成人项目。
