# 人设修改改为「原地保存 + 版本历史」（取代 ADR-0001 的「只允许衍生」）

| 项 | 内容 |
|---|---|
| 状态 | **已采纳，取代 [0001](0001-derive-instead-of-overwrite-persona.md)** |
| 决策日期 | 2026-11-07 |
| 影响范围 | 人设编辑流程、`PUT /v1/companions/{id}/persona` 的使用方式、人设页 |

## 背景

ADR-0001 规定：已创建的伴侣**不提供原地覆盖人设**，改人设一律衍生为新伴侣。

实际用下来有三个问题：

1. **改一个字就要换一个人。** 用户想把说话风格调冷一点，结果多出一个伴侣，旧对话还留在旧的她身上；
2. **伴侣数量快速膨胀。** 上限是 50 个，微调几次就逼近；
3. **「改坏了回不去」的担忧没有被解决。** 衍生只是绕开问题，用户仍然不敢改。

ADR-0001 自己在「后果」一节也写了：

> 后续若要支持「原地微调」，需另行决策，不能默认打开。

本决策就是那次「另行决策」。

## 决定

- 已创建的伴侣**支持原地修改人设**，保存后立即生效（从下一条回复开始）；
- 每次保存**生成新版本**，历史版本保留，可查看、可还原；
- 会话、消息、记忆、头像、音色**全部保留**，不因改人设而丢失；
- 「基于此版再造一个」作为**独立的高级操作**保留，不再是唯一的修改方式；
- 版本上限 **20 个**，超出后自动清理最旧的；
- **还原 = 把旧版本的内容复制成一个新版本**，不把版本号拨回去。

## 理由

- **符合直觉**：用户说的「改她」就是改她，不是「再造一个她」；
- **版本历史解决了真正的担忧**：ADR-0001 担心「覆盖后丢失过去」，版本历史让每一次改动都可回退，这个担忧不再成立；
- **关系连续性更重要**：会话和记忆是「这段关系的历史」，不应该因为调整了一句说话风格就断开；
- **还原也可撤销**：复制成新版本而不是回退指针，意味着「还原」本身也能再还原回来，不会造成不可逆操作。

## 后果

- 需要版本列表与还原接口（已实现：`GET /v1/companions/{id}/personas`、`POST /v1/companions/{id}/personas/{version}/restore`）；
- 版本表会增长，需要清理策略（已实现：保留最近 20 个）；
- 历史消息是在旧人设下生成的，改人设后**旧消息不会重写**——这是有意的，过去的话就该保持原样；
- 伴侣数量上限（50）的压力明显下降，因为微调不再产生新伴侣。

## 与 ADR-0001 的关系

ADR-0001 的**核心理由**（「关系是有历史的，覆盖会让人设和过去脱节」）仍然成立，但它给出的**解法**（禁止覆盖、只能衍生）过于极端。

本决策保留了那个理由，换了一个更好的解法：**允许覆盖，但让每一次覆盖都可回退**。

因此 ADR-0001 标记为「已被取代」，但其背景分析仍然值得阅读。
