# 同步范围先人设/会话/消息，记忆随后；消息只追加

## 背景

多端同步不可能一次全量。会话与消息是体验主线，记忆涉及合并与隐私，演练是低频数据。

## 决定

第一批同步范围：

- 人设（含版本）、会话、消息；
- 头像与设置暂不同步（本机偏好）；
- 记忆、演练记录第二批；
- **消息只追加、不修改、不物理删除**：删除用 `deleted_at` 墓碑，避免两端删除冲突；
- 人设采用版本号：两端都改时保留两个版本，提示用户选择，不自动覆盖。

## 理由

消息是事实流，追加 + 墓碑几乎消除冲突；人设是低频、可比较的，保留分叉比强行合并更诚实。
记忆合并需要语义判断，放第二批。

## 后果

- 消息表需要全局唯一 ID、设备 ID、逻辑时钟；
- 删除接口从硬删改为软删（现有 `delete_message` 需调整）；
- 人设同步需要版本列表与“分叉提示”，不能只同步 current_version；
- 导出/导入需要包含这些标识，否则跨端会重复。
