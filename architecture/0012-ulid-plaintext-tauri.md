# 标识、存储与打包：ULID + 明文同步 + Tauri

## 背景

阶段 0 需要定三个技术选择，它们会锁定数据模型与分发方式。

## 决定

1. **标识**：所有可同步实体使用 **ULID** 作为跨端唯一 ID；数据库仍保留自增主键用于本地索引。
2. **同步存储**：自建同步服务默认**明文存储**，文档与启动页明确风险；端到端加密列为后续可选，
   不做默认。单机模式不经过同步服务。
3. **桌面打包**：**Tauri**（现有 React 前端直接复用），不用 Electron。

## 理由

- ULID 短、按时间有序、字符串存储方便，适合离线写入后再合并；
- 端到端加密会让服务端无法做任何检索与排障，且密钥管理对自部署用户过重；
  先明文 + 风险说明，符合开源项目“用户自己负责部署”的定位；
- Tauri 安装包小、内存低，更适合个人自部署；现有前端零改动迁移。

## 后果

- 需要迁移：给伴侣、会话、消息、记忆、人设版本加 `ulid` 字段并回填；
- 同步服务代码不能假设能读明文做业务逻辑（为将来加密留边界）；
- Tauri 需要 Rust 工具链与签名流程，CI 要增加构建任务；
- Electron 相关方案不再考虑。
